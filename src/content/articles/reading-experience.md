这是一篇排版示例。阅读页的任务很直接：帮助读者持续理解内容。导航、装饰和交互都应该围绕这个目标展开。

## 给文字一个合适的宽度

当一行文字过长，读者换行时更容易失去位置；过短时，又会不断被换行打断。与其给所有设备固定字号，不如先约束正文最大宽度，再让容器在小屏幕上自然收缩。

```css
.article-body {
  max-width: 48rem;
  margin-inline: auto;
  line-height: 1.95;
  overflow-wrap: break-word;
}
```

中英文混排需要留意标点、代码和链接的视觉密度。正文中的代码可以有浅色背景，而整段代码则适合使用独立的滚动区域。

## 让层级提供方向

标题回答「接下来讲什么」，段落负责展开一个观点，列表用于平行的信息。不同元素承担不同职责，读者才不需要在每个段落都重新理解结构。

### 层级不等于更多装饰

可以通过字号、留白和字重建立秩序。颜色只需要承担少量明确用途：表达可交互内容、状态与重点。太多颜色会让重点彼此竞争。

### 为触摸和键盘同时设计

链接和按钮应该能用键盘聚焦，焦点位置必须清楚。手机上的操作区域也需要足够空间。一个小图标可以放在更大的按钮里，让视觉保持克制，同时容易点击。

## 明暗主题是一套完整关系

深色主题需要一起调整背景、正文、次要文字、分隔线和代码区域。直接把白色改成黑色，通常不能保持原来的层级。

| 角色     | 明亮主题       | 深色主题       |
| -------- | -------------- | -------------- |
| 页面背景 | 暖白，避免刺眼 | 深灰，保留层次 |
| 正文     | 深灰绿色       | 接近暖白       |
| 次要信息 | 保持足够对比   | 避免过暗       |
| 强调色   | 自然绿         | 较亮的柔和绿   |

首次访问可以跟随系统，手动选择后则尊重读者的偏好。主题设置只是浏览器偏好，不需要把它变成账号功能。

## 处理超出常规的内容

长代码、宽表格和数学公式都可能超过手机屏幕。让它们在各自区域中横向滚动，能保留信息并避免整个页面溢出。

```ts
const deliberatelyLongExample =
  '这是一条用于检查横向滚动的长代码行：abcdefghijklmnopqrstuvwxyz-0123456789-abcdefghijklmnopqrstuvwxyz-0123456789-abcdefghijklmnopqrstuvwxyz';
```

| 名称       | 描述               | 输入               | 输出               | 备注               | 验证方式       |
| ---------- | ------------------ | ------------------ | ------------------ | ------------------ | -------------- |
| 宽表格示例 | 此表用于小屏幕验证 | 一段较长的输入内容 | 一段较长的输出内容 | 应在表格区域内滚动 | 页面本身不溢出 |

公式也可以作为正文的一部分。例如增长模型 $a_n = a_0(1+r)^n$，在独立区域中可以写成：

$$
\sum_{k=0}^{n} ar^k = a\frac{1-r^{n+1}}{1-r},\qquad r\ne 1
$$

## 尊重减少动态效果的设置

微小的悬停变化有助于表达交互，但并非每位读者都需要动效。系统的「减少动态效果」偏好应该覆盖动画和滚动行为。

```css
@media (prefers-reduced-motion: reduce) {
  html {
    scroll-behavior: auto;
  }
  * {
    animation: none;
    transition: none;
  }
}
```

## 让检查回到真实阅读

在桌面、平板和手机上各读一遍文章。用键盘打开搜索，用窄屏查看代码，切换深色主题。把这些路径走通，往往比反复调整某个圆角更有价值。

好的阅读体验不一定会被读者直接注意到。它更像一条修整过的小路，让人顺着内容自然往前走。
