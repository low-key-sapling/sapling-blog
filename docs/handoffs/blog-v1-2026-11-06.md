## 按优先级继续

### 1. 修复唯一失败的浏览器测试定位

`tests/browser/site.spec.ts` 中 `mobile navigation works with a keyboard`，目前约第 78 行：

```ts
const menu = page.getByRole('button', { name: '打开导航' });
await menu.focus();
```

实际元素是原生 `<details>` 中的 `<summary aria-label="打开导航">`。当前 Chrome／Playwright 没有按上述 button 角色定位到它，测试在 focus 等待 30 秒超时，后续步骤没有执行。

建议改为 `page.locator('.mobile-menu summary')`，聚焦、按 Enter，确认展开并进入项目页。**目前是测试定位失败，没有证据说明菜单功能失效。**

失败产物：`test-results/site-mobile-navigation-works-with-a-keyboard-chromium/` 的截图、error-context.md 和 trace.zip。

## 需要保留的实现背景

- Markdown／MDX 使用 Astro 官方 unified processor。Zod 从 `astro/zod` 导入，避免已废弃的 `astro:content` 导出。
- **保留 `astro build --force`**。实测自定义 rehype 插件源代码变化后，普通构建可能复用旧 Markdown 缓存，造成源码已修但产物未更新。
- `rehype-accessible-content.mjs` 给表格和块级公式提供键盘焦点。公式容器设 `role="group"`，否则给普通 span 加 aria-label 会触发 axe。
- Mermaid 的按需包较大，Vite 报告部分 chunk 超过 500 kB。首页和不含图表的普通文章不加载它，已有性能结果达标；不要靠隐藏警告伪装解决。
- GrowthDemo 在 hydration 完成前禁用滑块，避免交互丢失；使用 `client:visible`。
- JSON 工具校验语法后只改空白，不使用解析后数值对象重新生成输出，保留大整数、长小数、指数和负零。
- npm override 统一 KaTeX 版本；Lighthouse 固定 13.5.0，以避开当时最新版引入的已知间接依赖问题；最近 audit 为 0。
- CUA 已查看首页并提交 completion_summary。没有创建远程 Site、没有公网发布、没有启动子代理、没有创建新聊天。
