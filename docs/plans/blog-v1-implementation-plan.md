# 个人技术博客 v1 设计与实施方案

- **版本**：v1.0
- **确认日期**：2026-11-05
- **状态**：2026-11-06 本地验收通过；环境、实测结果和复现命令见[本地验收记录](../verification.md)。尚未公网发布。
- **交付目标**：本地功能完整可用、视觉与测试通过，并具备静态部署和后续迁移能力。
- **前置调研**：[个人技术博客框架选型调研](../research/blog-framework-options.md)。

本文件记录已确认的实施基线。第 6、7 节的勾选限于本地源码、正式静态产物及服务模拟；第 5.5 节的真实服务配置和公网验证仍留到发布阶段。后续调整功能范围时，应同步更新本文件。

## 1. 目标与设计方向

建设以技术文章为核心的个人博客，优先服务中国大陆读者，托管、图片与统计服务优先使用免费额度。前期使用静态托管，后期可以迁移到自己的服务器。

| 维度     | 已确认的设计                                                                |
| -------- | --------------------------------------------------------------------------- |
| 技术栈   | Astro、TypeScript、Tailwind CSS、Markdown/MDX、Pagefind；交互区域使用 React |
| 视觉方向 | 封面卡片与杂志感，暖白／深灰背景搭配自然绿色，兼顾桌面和手机阅读            |
| 首页结构 | 个人简介、精选文章、最新文章；项目和工具通过导航进入                        |
| 明暗主题 | 首次跟随系统，手动切换后保存偏好                                            |
| 动效     | 少量克制动效，支持系统“减少动态效果”设置                                    |
| 界面语言 | 简体中文；文章允许中英文混写，不建立双语翻译版本                            |
| 品牌资料 | 暂用明确的占位站名、作者信息和示例内容，不编造真实经历                      |
| 定制方式 | 站点信息、导航、主色集中配置；布局和新页面通过组件代码扩展                  |
| 内容起点 | 从零开始，以明确标注的示例内容验收排版和功能                                |
| 写作方式 | 本地 Markdown/MDX 写作，通过 Git 管理和发布                                 |

## 2. 页面与功能

### 2.1 页面清单

| 页面／模块 | 第一版实现内容                                                           |
| ---------- | ------------------------------------------------------------------------ |
| 首页       | 简介、精选文章、最新文章、封面卡片及分类标签                             |
| 文章列表   | 按发布时间倒序、分页，默认每页 9 篇                                      |
| 内容组织   | 分类、标签、按年月归档、系列目录及系列内上一篇／下一篇                   |
| 文章详情   | 摘要、发布时间、更新时间、目录、阅读进度、返回顶部、复制链接、收藏、评论 |
| 技术排版   | 代码高亮、行号、复制、提示块、表格、图片、Mermaid 流程图、数学公式       |
| 交互演示   | 作者编写 React 组件，通过 MDX 嵌入文章，并提供一份完整示例               |
| 全站搜索   | 搜索文章、项目详情、工具介绍、关于及友链内容；结果区分内容类型           |
| 收藏与续读 | 独立收藏页、添加与移除收藏、记录阅读位置，再次打开时提示继续阅读         |
| 关于页     | 可维护的个人简介、技术方向和社交链接                                     |
| 项目展示   | 项目列表及独立详情页，支持技术栈、截图、实现介绍、源码和演示链接         |
| 友链页     | 手动维护名称、介绍、头像和链接                                           |
| 工具箱     | 工具目录，以及 JSON、Base64、时间戳三个独立工具页                        |
| 订阅与索引 | RSS 摘要订阅、sitemap、页面元数据、分享信息和 404 页面                   |

### 2.2 浏览器工具

| 工具   | 行为要求                                                             |
| ------ | -------------------------------------------------------------------- |
| JSON   | 严格校验、格式化、压缩、错误提示、复制与清空；格式化不得改变数值含义 |
| Base64 | 支持 UTF-8 文本与中文编解码，明确提示非法输入                        |
| 时间戳 | 支持秒／毫秒与日期时间互转，默认北京时间，可切换 UTC                 |

工具输入仅在浏览器处理，不上传、不自动保存。

### 2.3 收藏与阅读状态

- 收藏和阅读记录仅保存在当前浏览器，不需要登录，不跨设备同步。
- 通过统一的浏览器存储模块管理收藏和阅读位置。
- 存储不可用或记录损坏时，页面仍可正常阅读。
- 文章被移除后，收藏页能够处理失效记录。
- 续读采用提示恢复，不自动打断读者当前位置。

## 3. 内容模型与写作发布

### 3.1 内容模型

使用 Astro Content Collections 管理内容，集中校验必需字段。

| 模型         | 字段与职责                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------------- |
| `Article`    | 稳定标识、标题、摘要、发布日期、可选更新日期、分类、标签、可选系列与顺序、封面、草稿状态、精选状态 |
| `Series`     | 稳定标识、标题、介绍；文章按明确顺序组成系列                                                       |
| `Project`    | 稳定标识、名称、简介、技术栈、封面、外部链接和详情正文                                             |
| `Friend`     | 名称、地址、简介及可选头像                                                                         |
| `SiteConfig` | 站点与作者信息、导航、主题参数、社交链接、评论和统计配置                                           |

文章使用稳定的 `/blog/<slug>/` 地址，项目使用 `/projects/<slug>/`。修改标题或迁移域名不改变路径。

### 3.2 写作与发布规则

1. 在本地使用 Markdown/MDX 写作，图片与文章共同保存，通过 Git 管理。
2. 草稿可在本地预览；发布时显式修改状态并提交。
3. 正式构建统一排除草稿，包括详情页、列表、系列、搜索索引、RSS 和 sitemap。
4. 图片在构建时优化；缺少封面时使用统一设计的默认封面。
5. RSS 输出最近 50 篇已发布文章的摘要和原文链接。

首版采用草稿与手动发布流程，不包含定时发布和线上私密草稿预览。

## 4. 渲染、搜索与交互结构

### 4.1 页面与正文渲染

- 基于 Astro 基础项目建立自定义布局和组件，采用静态输出。
- Markdown 与 MDX 使用统一的 unified 渲染管线，代码使用 Shiki，公式在构建时渲染。
- Mermaid 仅在需要的文章中加载。
- React 只用于工具和作者预先编写的交互演示；普通页面、导航及正文不依赖 React 才能显示。
- 提供可复用的正文组件与完整的 MDX 交互示例，作为后续文章和页面扩展的参考。

渲染扩展采用 Astro 官方提供的 [unified 接口](https://docs.astro.build/en/reference/markdown-processors/unified/)。

### 4.2 全站搜索

- Pagefind 在静态构建完成后生成中文搜索索引。
- 索引覆盖文章、项目详情、工具介绍、关于及友链内容。
- 搜索结果区分内容类型。
- 排除导航、评论、表单和收藏状态等内容。
- 搜索索引与静态页面一起部署和迁移。

### 4.3 静态产物

构建流程应产出可由普通静态服务器提供的页面、资源、搜索索引、RSS 和 sitemap。发布后的内容展示与浏览器工具不依赖自建业务服务端。

## 5. 外部服务、环境与部署

### 5.1 评论

- 使用 giscus，读者通过 GitHub 账号发表评论。
- 仅在文章详情页加载，使用稳定页面路径关联 GitHub Discussions。
- 支持明暗主题同步。
- 配置缺失时不请求服务，加载失败时不阻塞阅读。

服务配置依据 [giscus 官方说明](https://giscus.app/zh-CN)。

### 5.2 访问统计

- 默认接入 Cloudflare Web Analytics，仅站主查看，不展示公开阅读量。
- 只接入页面访问统计，不主动上报工具输入、收藏内容或搜索词。
- 统计脚本与正文独立加载，未配置或加载失败时不影响站点功能。
- 迁移到自己的服务器后保留同一统计接入方式。

Cloudflare Web Analytics 支持非 Cloudflare 托管站点，配置参考其[官方说明](https://developers.cloudflare.com/web-analytics/about/)。

### 5.3 托管与迁移

- 提供 Cloudflare Pages 的 Git 自动部署说明。
- 准备 Nginx 静态托管配置，支持后续迁移到自己的服务器。
- 两种部署方式使用相同的静态构建产物。
- 正文、图片、字体及主要脚本尽量同源提供；外部评论和统计独立加载。
- 实际中国大陆公网访问表现留到发布阶段验证。

Cloudflare Pages 配置参考 [Astro 官方部署指南](https://developers.cloudflare.com/pages/framework-guides/deploy-an-astro-site/)。

### 5.4 开发与构建环境

- 统一使用 Node 24 LTS 和 npm，提交依赖锁文件。
- 方案确认时，本机 Node 版本为 22.22.2，低于当时已核实的当前 Astro 要求；实施时准备项目独立运行环境。
- 提供本地开发、类型检查、测试、构建及构建产物预览的使用说明。
- 提供可重复执行的构建检查流程。

## 8. 首版范围边界

首版不包含以下能力：

- 账号系统和个人服务端数据空间。
- 网页文章编辑后台和页面可视化拖拽拼装。
- 读者可编辑并运行代码的 Playground。
- 邮件订阅、定时发布和线上私密草稿预览。
- 跨设备收藏或阅读进度同步。
- 中英双语界面和文章翻译版本。
- 旧博客内容迁移。
- 实际公网发布，以及真实评论、统计和域名配置后的公网验收。

上述能力若后续进入实施范围，应单独记录需求变更及其对数据、服务和部署的影响。
